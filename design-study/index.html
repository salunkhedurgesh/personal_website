My recommendation

Use Research Atlas as the foundation, borrow Field Notes’ explanatory voice, and reserve Instrument’s darker canvas for simulations. Maintain one navigation, type scale, and interaction language across all three contexts.

Students: “Could I work on this?”

A question, a picture, a starting lesson, and a clear contact route. Define specialist terms on first use rather than asking students to decode the bibliography.

Peers and reviewers: “What is the contribution?”

Evidence within one click: publications, methods, artifacts, collaborators, and limitations. Explain your contribution on each research story without overstating individual authorship.

Visual language & interaction

Precision, calm, and readable depth.

Take Apple’s emphasis on hierarchy, legibility, consistent controls, and purposeful materials as principles. For this research site, I would translate them into open layouts and quiet surfaces, with the science providing the visual interest. This is a web-specific interpretation of the Human Interface Guidelines.

ElementProposed rule and reason
FontsOne sans-serif family for Atlas: system fonts now; consider self-hosted Inter for consistent rendering later. Regular body and medium/semibold headings. Field Notes can pair Georgia headlines with sans-serif body. Keep monospace for equations, code, and numeric readouts.
Type sizeBody 18px desktop, 17px mobile; reading line height 1.55–1.65; metadata 14–15px; section headings 32–48px; hero 42–76px. Use rem/clamp and preserve browser zoom. These are proposed web values, not Apple’s native point-size specifications.
LayoutReading columns around 60–70 characters; overall width around 1180px. Single-column mobile flow, visible navigation labels, predictable heading hierarchy. Use a 4/8px spacing rhythm and more space between sections than between related elements.
Color rolesNeutral surfaces support sustained reading; deep teal identifies actions; a restrained warm color distinguishes a figure’s second configuration. Pair plot colors with line patterns and labels. Do not turn scientific colors into random decorative accents.
SurfacesUse mostly flat surfaces, fine separators, and 8–16px corner radii. A modest translucent navigation layer could be tested later with an opaque fallback; text and plots should sit on stable, readable backgrounds.
Buttons and linksOne prominent action per section, with quieter secondary links. Labels name outcomes: “Read paper,” “Compare configurations,” “Explore the course.” Links navigate; buttons act. Include hover, pressed, keyboard focus, and disabled states where relevant.
Filters and togglesPublication topics use labelled filter buttons, with the selected state and result count announced. Year uses a select. Switches belong to independent on/off settings such as “Show joint limits.” Tabs belong to views of the same object, such as “Overview / Method / Resources.” Avoid redundant controls.
InteractionKeep titles and summaries visible; disclose full abstracts on request. A future simulator should have explicit Run/Pause/Reset, a clear initial state, keyboard-operable controls, and a text explanation. No essential information should depend on hover or dragging.
MotionFor ordinary controls, try subtle 120–180ms transitions. Scientific animation should be user-initiated and explain something. Respect reduced-motion preferences. Keep the homepage lightweight, then load a simulator only when opened.
AccessibilityAim for WCAG 2.2 AA: normal text contrast ≥4.5:1, large text ≥3:1; clear focus, labels, keyboard access, and reflow at 320 CSS pixels. Prefer at least 44×44 CSS px targets for major controls; WCAG AA’s minimum is 24×24 with exceptions. Test at 200% text size. Full conformance needs an implementation audit.

Later · exploration

Three doorways into the playground.

01 · COMPARE

One position, multiple configurations.

Use existing inverse-kinematics lessons as the basis. Begin with a simple model, then show a real robot. A later implementation can compare legal and unrestricted solutions explicitly.

02 · FOLLOW

Can posture change without a singularity?

Adapt the existing cuspidality examples into a guided sequence. Connect the joint-space motion to the actual tool path.

03 · CHOOSE

Same path. Different outcome.

Let a student compare starting configurations and see where a joint limit blocks continuation. Explain the distinction between point reachability and whole-path feasibility.

These are concepts for a subsequent phase. The teaching repository provides strong foundations, but its modules have different dependencies and deserve a focused integration review. Keep course attribution and distinguish sampled evidence from mathematical guarantees.

Reading behind the recommendations

Design references.

  • Apple: Typography — legibility, weight, hierarchy, and restraint with font families.
  • Apple: Color — consistent meanings and adaptation to context.
  • Apple: Buttons — clear actions, spacing, and prominence.
  • Apple: Materials — materials serving interface structure.
  • W3C: WCAG 2.2 — contrast, reflow, keyboard interaction, and focus.
  • W3C: Target size — minimum sizes and spacing exceptions.
  • W3C: Animation from interactions — reduced-motion considerations.
